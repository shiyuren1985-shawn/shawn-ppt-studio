# Fast 4×3 运行合同

只在用户选择 `fast_4x3` 时读取。4×3 是 Fast8 共享主干上的三页薄适配，不维护第二套来源、提示编译、并发或恢复管线。

## 默认代表页选择（仅限自由选页）

用户未指定页码且没有压力测试等专项目的时，先选一张核心命题和视觉关系明确、但视觉解法尚未被固定图表、固定层级、固定版式或大量必显元素锁死的风格释放页；再搭配一张数据/对比页检验信息组织，以及一张复杂架构或高密度页检验复杂承压。用户指定页码或测试目的时逐字服从，不重新选页。这是一次轻量判断，不建立评分器或新增审核。

## 准备

1. 用 `build_4x3_source_packet.py` 同时写入 `state/director_inputs/authoritative_three_page_packet.md` 与 `authoritative_snapshot_source.json`，冻结恰好三页。
2. 每个新 `project_dir` 都创建三位新的 `fork_turns=none` 短导演：事实内容、标题资产、三页视觉系统。三者只读本轮冻结包、本轮参考图分析和本轮正式路径，不复用历史会话或旧路径。
3. 逐页资产 bundle 由 `merge_4x3_director_inputs.py` 写入各页内容合同；只有真实 PNG/JPEG/WebP 可进入 ImageGen 附件，规划证据只作 supporting source。标题 schema 与 Fast8 共用，按页投影唯一标题。
4. 三位导演退出后只调用 `four_by_three_control_plane_v1.py prepare-directors --state <state>`；正式标题、合同、layout、source snapshot、global chrome、任务和工程路径均从同一 state 推导，不人工传第二套路径。

## 生成与收口

A–D 四张锚点同波。一个图片执行子 Agent 使用 `prompts/4x3-burst-runner.md` 的唯一机械入口；哪个锚点先结算，就只解锁同风格两张跟随页并滚动补派。12 个节点与 Fast8 共用中央 ImageGen cap5，已有 claim、receipt 或 recovery queue 时先恢复、结算或明确终止，禁止重复生图。

跟随页只继承本风格的色彩、字体、材质、图像工艺和完成度；本页标题、事实、对象、关系命题与构图只来自本页冻结合同。事实或品牌附件占满 5 个时才机械降级为文字化视觉家族，不增加 Reviewer 或丢弃必要资产。

12 张齐备后执行 `four_by_three_control_plane_v1.py lean-finalize --state <state>`，生成 `overview/ABCD_4x3.png`、标记 `candidate_ready` 并写 handoff。选择前不做阻塞式完整视觉 QA；只有明确内容硬伤或锚点实质同构可触发一次定向修复。

## 共享边界

Fast8 主干唯一维护 content v2、prompt v4、四字段创意合并、空间与工艺合同、global chrome、附件上限、输入指纹、来源冻结、正式 job、PNG 校验、技术重试、无生图恢复、中央租约和媒体隔离。4×3 只维护三页 bundle、A–D 跨页家族、`anchor → two followers` 依赖图及其总览形态。

不要把 Fast8 的 A–H 数量、单页终局差异 Judge、两行 A–H 交付格式或至多两席替代规则硬套到 4×3；也不要为 4×3 复制共享实现。
