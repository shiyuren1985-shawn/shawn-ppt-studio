# 阶段交接与源材料漂移

本文件定义新运行的来源封存、漂移门禁和跨对话交接。它不改变 Quick8、Fast 4×3、Strict 4×3 的候选数量、并发、恢复、QA 或 `candidate_ready` 语义。

`style_run_state.json` 或 `selected_style_run_state.json` 始终是唯一进度真相。`source_snapshot.json` 是只读输入基线，`handoff.json` 是可重建的派生检查点；不得把 handoff 当成第二份可编辑状态。

## 文件位置

新运行在 `<project_dir>/state/` 使用：

```text
task_init.json
source_snapshot.json
source_drift_status.json
legacy_source_confirmation.json
handoff.json
handoff.md
run_health_report.json
run_health_report.md
```

- `task_init.json` 只由 `init_task_dir.py` 为新目录创建，声明该运行必须先有快照；`--resume` 不给旧项目补写。
- `source_snapshot.json` 在首轮图片任务派发前封存一次，之后不得覆盖或用当前文件反推历史哈希。
- `source_drift_status.json` 记录最近一次显式检查、warning 或阻断结果。
- `legacy_source_confirmation.json` 只在用户明确接受旧任务无历史快照风险时创建；它是独立、带运行身份和动作范围的 sidecar，不写回旧状态，也不生成历史哈希。
- `handoff.json` 是正式机器可读交接；`handoff.md` 只能由它确定性生成。
- `run_health_report.json|md` 是 `process_completed` 与 handoff 落盘后从正式证据派生的非视觉技术报告；它不是交接的一部分，失败不影响已封存状态或交付。
- 旧任务不迁移、不补写 `source_snapshot.json`，也不重写历史状态。

## 初始化与封存

新建任务的 `task_init.json` v1 只含 `task_init_contract_version`、绝对 `project_dir`、`source_snapshot_required=true` 和 `created_at`。它不是源快照；作用是让新任务在缺少 `source_snapshot.json` 时 fail closed。`snapshot-source` 只接受带有效 v1 初始化合同的新目录；即使旧状态尚无事件、候选或尝试，也不得把当前哈希补写成历史基线。中断若留下“快照已写、状态尚未绑定”的孤儿文件，只允许在没有任何生成历史、任务带有效初始化合同且本次输入与孤儿快照完全一致时补齐状态绑定；不得覆盖或改写该快照。

在内容合同、本次页面范围和真正路由到图片任务的少量参考资产确定后、首次派发前运行：

```bash
python3 scripts/pipeline_control.py snapshot-source \
  --project-dir "<project_dir>" \
  --state "<project_dir>/state/style_run_state.json" \
  --source-file "<权威大纲或源文件绝对路径>" \
  --page-ids "02,05,08" \
  --content-contract "<project_dir>/content_contracts/page_02.json" \
  --content-contract "<project_dir>/content_contracts/page_05.json" \
  --content-contract "<project_dir>/content_contracts/page_08.json" \
  --supporting-sources-json '["/绝对路径/当前页说明.md","/绝对路径/案例证据.pdf"]' \
  --assets-json '[{"path":"/绝对路径/logo.png","asset_type":"required_asset","role":"official_logo","style_slots":["A","B","C","D"]}]'
```

`supporting_sources` 与 `assets` 是两套不同清单：前者是创建内容合同时实际依赖的当前页说明、证据文档、视觉政策或项目资料，只做来源追溯和漂移检测，不传给 ImageGen；后者只记录真正进入图片任务、提示编译或独立标题 QA 的外部资产。不得为了“把来源也锁住”而把 `.md/.docx/.pptx/.pdf` 规划来源伪装成 generation asset。

资产席位路由的正式作者字段是 `style_slots`。为避免已生成的快照记录被重新输入时丢失路由，控制器也接受同义的 `styles|used_by`；多个字段同时出现时必须规范化为同一席位集合，否则在快照落盘前阻断。不要再靠读取已写快照后人工发现 `used_by=[]` 才重建整个运行目录。

Quick8 探索运行只封存当前候选页；4×3 必须精确封存锚点和两个 follower，不能用 `--source-page-ids` 缩小或扩大模式规定的范围。新选定风格扩页先冻结覆盖完整 `page_order` 的 authoritative expansion packet，三位导演只读该 packet；`prepare-directors` 再原子生成逐页 v2 内容合同、正式 v4 job、实际附件清单和 source snapshot。每个正式页面必须且只能绑定一个匹配 `page_id` 的内容合同。primary 与可选 supporting 锚点作为本次视觉导演输入冻结；`anchor_input_mode=text_family` 的页面不把锚点原图虚报为该页实际 ImageGen 附件，`raster` 页面则必须精确记录锚点路径和 SHA。合同集合、导演输入和外部附件集合必须与正式 job 的声明一致。资产库中“存在”的文件不能自动成为已使用资产，只有真正进入导演输入、正式图片任务、提示编译或独立标题 QA 的参考图、Logo、共享必要资产、`required_page_assets`、`global_chrome_contract` 与 QA 参考才进入本轮冻结身份；内容合同里未被编译器路由的字段不得虚报为“已使用”。

也可在首次 `prepare-anchors` 中附加 `--source-file`，让脚本按模式推导页码并创建快照；4×3 此时必须已经存在全部三页内容合同。新 Fast8 优先使用这一原子路径：脚本会从持久化的 `state/preflight_manifest.json.required_files` 自动提取除权威源、内容合同和实际资产之外的 `supporting_sources`，避免主控手工重复两套清单。只有非 Fast8、旧兼容或确需人工审阅复杂封存范围时才优先单独运行 `snapshot-source`，并明确分开 `--supporting-sources-json` 与 `--assets-json`。

稳定提取支持：

- Markdown/文本：优先用 `P02`、`Page 2`、`第 2 页` 等页面标题分段；若权威大纲以标准 Markdown 表格存页，则允许首列精确匹配这些页码标识，并把同一表格的表头、分隔行与目标记录一起规范化绑定。标题段或表格首列出现多个同页匹配时都必须阻断，不能取第一项猜测；只在其他列提到页码不构成页面记录。
- JSON：按 `page_id|page|slide_id|slide|id` 或对应页面键定位；同一目标页出现多个匹配记录时同样阻断。
- PPTX/PPTM：按演示文稿中的实际幻灯片顺序提取 DrawingML 文本。
- 无法稳定定位页面的格式：显式提供独立 `--source-fragment-file`；纯文本 fragment 只能绑定一页，多页必须用可按页定位的 JSON。默认 `--source-fragment-authority extractor_aid`，fragment 只是辅助提取件，不替代权威源；权威源变化而 fragment 未变时无法证明本页未变，必须阻断并重新确认。新 Fast8 使用脚本生成的 `authoritative_page_fragment` 作为本次运行的冻结输入：运行中不再读取、哈希或检查原大纲，也不因其变化 warning/重做；fragment 自身、内容合同和实际资产变化仍必须阻断。旧模式使用 `authoritative_page_fragment` 时继续按其原合同处理。

无法证明当前页范围时必须停止封存，不能退化为“拿整个文件哈希冒充页面内容哈希”。整个 Office 包的 SHA-256 用于诊断；是否阻断以相关页规范化内容、内容合同和实际使用资产为准。

## 漂移检测

在以下边界先运行 `check-source-drift`：

- `init_task_dir.py --resume` 找到旧目录后、任何新动作前；
- 定向修复候选前；
- 用户选定风格后扩页前；
- 继续生成 Fast/Strict 跟随页或后续页面前；
- 向下游 PPTX 装配交接前。

```bash
python3 scripts/pipeline_control.py check-source-drift \
  --state "<project_dir>/state/style_run_state.json" \
  --action "resume"
```

正式动作不得使用 `--report-only` 绕过门禁。脚本还会在 `prepare-anchors` 的恢复分支、`prepare-fast-anchor-repairs`、`prepare-fast-followers`、`prepare-followers`、非恢复型 `record-dispatch-wave`、扩页生成动作开始、完成态校验和 handoff 写入前复核。当前动作的运行模式、完整页范围、合同路径和外部输入资产还必须与封存清单一致；图片任务中的 `source_content_contract_path|sha256`、`imagegen_referenced_paths`、`imagegen_input_manifest` 及探索管线的 prompt/input fingerprint 在派发前交叉复核。正式附件字段与真实附件清单必须同路径、同顺序且无重复。新 Fast8 探索 Worker 只接收 `record-dispatch-wave` 返回的 `worker_ticket_path`，由 `check-fast8-worker-ticket` 机器校验并取得 job 路径与 SHA；其他探索管线仍读取正式 `generation_job_path` 并核对同项 `generation_job_sha256`。所有 Worker 都不得自行拼接任务路径。只有当前动作允许复用的同风格锚点或待修复候选可视为内部生成输入，其他风格或其他 follower 图片不得绕过资产覆盖。`validate-state --complete` 属于只读审计：允许刷新 `source_drift_status.json` sidecar，但不得改写已完成的正式 state，否则会自我破坏 handoff 的状态哈希绑定。

新选定风格扩页不创建每页一个 Agent。`prepare-directors` 锁定正式 jobs 后，唯一机械执行 Agent只调用 `selected_style_control_plane_v1.py render-action --state <state>`；控制面逐页校验 action、attempt、正式 job、合同 SHA、附件顺序和输入指纹。不得把临时手写的合同、资产 JSON 或第二套路径当成门禁输入。旧扩页的 `check-expansion-job` 与逐页 Worker 只按已落盘 job 恢复。

若全稿标题系统由权威大纲一次授权，`global_chrome_contract.authorization.source_path` 只保留授权来源与定位证据，不再作为页面实际使用资产重复进入 `assets[]`。页面生成的硬依赖是已编译 `global_chrome_contract` 的路径与 SHA、实际 Logo/QA 参考资产，以及当前页的冻结 `authoritative_page_fragment`。新 Fast8 不再检查原大纲是否变化；当前页冻结片段、已编译标题合同或实际资产变化仍然硬阻断。

判断矩阵：

| 当前结果 | 状态 | 是否可继续 |
| --- | --- | --- |
| 整个源、相关页、内容合同、实际使用资产均未变化 | `unchanged` | 是 |
| 整个权威源 SHA-256 变化，但相关页规范化内容、合同和资产未变化 | `warning_unrelated_source_change` | 是；记录 warning |
| 相关页规范化内容变化或无法再稳定提取 | `source_drift_detected` | 否 |
| 任一相关内容合同变化或缺失 | `source_drift_detected` | 否 |
| 任一当前页规划／证据来源变化或缺失 | `source_drift_detected` | 否 |
| 任一实际使用资产变化或缺失 | `source_drift_detected` | 否 |
| 当前动作换用了快照外的页面、合同路径或外部资产 | `source_drift_detected` | 否 |
| 正式状态的 `run_mode` 与快照不一致 | `source_drift_detected` | 否 |
| 正式状态的完整页面范围变化、缺页或出现语义重复页码 | `source_drift_detected` | 否 |
| 同一目标页在 Markdown/JSON 中重复，无法唯一定位 | `source_drift_detected` | 否 |
| 使用默认 `extractor_aid` fragment 且权威源发生变化 | `source_drift_detected` | 否；无法证明本页未变 |
| 新 Fast8 使用冻结 `authoritative_page_fragment`，上游大纲随后变化 | `unchanged` | 是；不检查、不 warning、不重做 |
| 新选定风格扩页已经冻结 authoritative expansion packet，上游大纲随后变化 | `unchanged` | 是；本轮不检查、不 warning、不重做；只影响新运行 |
| `authoritative_page_fragment` 自身变化或缺失 | `source_drift_detected` | 否 |
| 扩页某一页的冻结 packet 记录、内容合同、正式 job 或实际附件不一致 | `source_drift_detected` | 仅阻断该页；其他冻结且无关页面继续 |
| 新状态声明 source guard，但快照缺失 | `source_snapshot_missing` | 否；不得降级 |
| 旧任务没有快照 | `legacy_snapshot_missing` | 来源完整性仍为否；仅可在独立确认 sidecar 授权的具体动作内兼容继续 |

阻断时不派发新图片任务、不增加 attempt、不出队、不占并发槽位，并在状态的 `source_integrity.status` 与 `source_drift_detected` 标记结果。必须重新确认内容合同或建立新运行目录；不得静默让旧候选匹配新内容。

已经派发的任务仍可 `settle-wave`，已有产物仍可走 `recover_artifact`，filesystem QA、`candidate_ready` 和总览文件落盘也不因漂移被改写；但不得把它们正式交付或向下游移交。恢复派发必须使用 recovery-only 波，不与新生成混在同一波。只有新的生成、修复、扩页或正式交付重新经过门禁，因此图片次数、并发上限、恢复预算和 QA 语义保持不变。

修复图片调用在两种无生图恢复都返回 `not_found` 后若按既有预算获准技术重试，脚本只从上一尝试的正式 repair job 确定性复制下一 attempt 文件：除 `attempt` 外，内容合同、提示、附件顺序、输入清单、指纹和输出目标均保持不变；不得临时重写任务或扩大输入。

Quick8/Fast8/4×3 用户选定方向后，先检查选中锚点文件仍与选择时绑定一致，再为完整扩页范围创建新的 `project_dir` 和 `run_mode=selected_style_expansion` 状态。initializer 冻结覆盖全部 `page_order` 的 expansion packet 和锚点导演输入；三位导演与 `prepare-directors` 只基于这次冻结身份创建正式合同、jobs、附件 manifest 和快照。packet 冻结后不再读取或比较仍在变化的上游完整大纲，上游后续修改只影响新运行。每次扩页启动只传正式 state，控制面从中推导 job、合同和实际图片输入，禁止手写第二套清单。不得用探索运行的单页快照冒充多页扩页快照。

## Legacy 安全兼容

旧项目没有 `source_snapshot.json` 时：

1. 明确报告 `legacy_snapshot_missing`，不得把当前 SHA-256 写成“生成时快照”。
2. 允许只读检查旧状态和现有产物元数据；既有恢复与结算逻辑保持兼容。
3. 需要继续生成、修复、扩页或候选交付时，优先建立新运行目录；确需兼容继续时，必须先由用户明确确认，再运行：

```bash
python3 scripts/pipeline_control.py confirm-legacy-source-risk \
  --state "<project_dir>/state/style_run_state.json" \
  --actions "generation_dispatch,targeted_candidate_repair" \
  --user-confirmed
```

4. 脚本只创建 `state/legacy_source_confirmation.json`，记录确认 ID、风险码、确认时间、确认人/文字、当时状态 SHA、事件数、绝对状态路径、`run_id`、`project_dir`、`run_mode`、页范围、选中风格及精确动作白名单。运行身份或动作不匹配即不授权；向旧 state 手工注入同名字段无效。
5. 授权后结果仍保持 `status=legacy_snapshot_missing`、`can_continue=false`、`source_integrity_verified=false`，另以 `operation_authorized=true` 表示仅该动作可兼容执行；不能把它解释为“未漂移”。新任务声明快照但快照缺失、真实漂移或正式 handoff v1 永远不能由该确认绕过。
6. 兼容派发只绑定既有旧 job 的绝对路径和当前 SHA-256，不要求重编现代 manifest；不迁移旧目录、不重编旧任务、不改写旧状态版本。

## `handoff.json` v1

候选和正式总览已落盘、页面达到 `candidate_ready|accepted`、全部完成门禁通过、准备交付时生成。`formal_overview_completed` 只登记总览，不提前写正式 handoff；`process_completed` 封存最终状态后自动生成一次。显式命令也只允许在 `status=completed` 且已有 `process_completed_at` 后运行：正式文件已存在且绑定当前状态时只做幂等验证，若仅缺 `handoff.md` 则从 JSON 确定性重建，不覆盖现有 `handoff.json`，也不允许通过参数改写已封存交接：

```bash
python3 scripts/pipeline_control.py write-handoff \
  --state "<project_dir>/state/style_run_state.json"
```

旧版本若曾在完成态校验时把漂移 warning 写回 state，可能造成 `handoff.state_ref.sha256` 失配。只有确认运行身份相同、当前漂移仍允许继续时，才使用一次显式安全修复；命令会先保留 `handoff.before_refresh_<sha>.json`，再从当前正式 state 确定性重建，不能用于绕过真实源材料漂移：

```bash
python3 scripts/pipeline_control.py write-handoff \
  --state "<project_dir>/state/style_run_state.json" \
  --refresh-state-ref
```

`candidate_ready` 在 handoff 中仍表示只完成确定性文件检查，通常保持 `qa_stage=filesystem`、`qa_scope=filesystem_only`；不得描述成正式视觉验收通过。

生成 handoff 时会在最终写入边界重新执行一次实时漂移检测，调用者较早取得的 pass 结果不能复用。Fast8 还要求最终 `pass|best_effort` 报告存在、哈希有效并绑定当前 A–H 集合。所有正式路径必须是存在的绝对本地路径；运行模式必须非空，用户选择必须指向正式候选，handoff 页范围和 `page_content.pages` 必须与快照范围一致。候选要求 16:9；矩阵总览只要求是有效正尺寸 PNG。SHA-256 由文件字节计算；根任务不打开图片。`process_completed` 后 v2 正式状态封存，不再接受页面、QA 或全局事件；因此 `handoff.state_ref.sha256` 保持与最终状态一致。

`handoff.md` 只使用 `handoff.json` 中的路径、哈希、尺寸、状态、漂移 warning、问题和下一步动作确定性重建；重建不读取旧聊天、JSONL、子 Agent 输出，也不重新打开或解析图片。创建 JSON 时已经做过文件存在性和哈希校验，因此后续即使文件临时离线，仍可从同一 JSON 重建同字节 Markdown。

`run_health_report.json|md` 只读取已封存状态、任务、路径、哈希与计时，不改写 handoff，也不进入 `validate-state --complete` 硬门。完整集中索引和最近 10 次复盘规则见 `运行监测与批次复盘.md`。

## `handoff.md` 与媒体隔离

`handoff.md` 只展示继续工作必需的运行身份、来源哈希、内容合同、实际资产、候选路径/尺寸/哈希/状态、总览普通文件链接、用户选择、未决问题和下一动作。它明确告诉新对话无需读取旧聊天或旧 JSONL。

禁止写入 handoff：

- Base64、data URI、图片像素或缩略图；
- Markdown 或 HTML 图片嵌入；
- 大段日志、完整提示、子 Agent 原始输出；
- 需要旧聊天才能解释的隐式状态。

需要重建 Markdown 时只运行：

```bash
python3 scripts/pipeline_control.py rebuild-handoff-md \
  --handoff-json "<project_dir>/state/handoff.json"
```

该命令不扫描聊天、日志或“最新文件”，相同 `handoff.json` 必须生成字节一致的 `handoff.md`。
