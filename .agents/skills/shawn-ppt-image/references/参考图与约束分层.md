# 参考图与约束分层

## 目的

让参考图直接承担高维视觉指导，文字只说明用户为什么喜欢它、哪些部分不要复制。约束事实与风险，不把视觉解法提前写死。

核心原则：

> 提炼用户意图，不提炼视觉配方。对结果具体，对实现手段克制；对事实硬，对美学软；详细规则用于 QA，生图提示保持精简。

## 输入优先级

发生冲突时按以下顺序处理：

1. 事实、数据、来源、品牌和用户明确的硬要求。
2. 用户明确说明的参考意图与不复制边界。
3. 实际传入的参考图或已选锚点图。
4. Skill 的通用设计与空间建议。

通用建议不得覆盖用户明确意图。文字合同不得取代参考图，只负责选择参考图中真正需要继承的维度。

资产库、历史稿和旧母版不在授权优先级中。只有当用户明确把某张 master/reference 指定为标题区依据时，它才参与标题要求；普通风格参考图不能默认为当前页增加 Logo 或标题区。大纲或用户当前要求没有标题区说明时不创建 `global_chrome_contract`，页面自由发挥；有说明时合同只转录其关系和大致位置，不要求像素级复刻。

## 五层约束

### 1. `hard_invariants`

只放必须精确的内容：

- 关键事实、数字、来源和名称。
- 并列、顺序、因果、归属、包含等语义关系。
- 指定 Logo、品牌版本、语言、16:9 和必要输出要求。
- 用户明确指定的页面外壳关系，例如 Logo、主标题和副标题的相对层级。

写法应短而具体。只有事实错误、品牌错误、可读性或几何稳定性问题才能形成负面硬约束。

### 2. `reference_intent`

有参考图时，根任务不得再次打开、嵌入或接收图片载荷；只把明确授权的本地路径交给隔离视觉导演或 Judge。隔离子 Agent 可以按任务需要打开参考图和必要单图，但只向父级写入精简文字、JSON、路径与哈希，不回传图片块、缩略图、Base64 或 data URI。没有可用的隔离视觉通道时明确标记尚未分析，不得由根任务代看：

- `borrow`：用户希望借鉴的少量感知结果，例如空间节奏、信息密度、材质或排版气质。Fast8 与 Fast 4×3 都对本席位实际收到的全部风格参考合并去重后，只把 2–3 个核心感觉写进提示，不按每张图重复展开。共享参考感觉不得覆盖或合并艺术导演中各席 run-local 的 `visual_thesis` 与 `craft_axis`。
- `do_not_copy`：不需要复刻的内容，例如标题样式、具体构图、原图文字、物体和节点位置。
- `priority`：`primary|supporting`，说明该图在当前席位中的角色。

参考图对象推荐结构：

```json
{
  "path": "绝对路径",
  "role": "primary_style_reference",
  "style_slots": ["C", "D"],
  "tones": ["light"],
  "reference_intent": {
    "borrow": [
      "低压力但不空洞的空间节奏",
      "适中的信息密度",
      "用少量图标与精细线条讲清复杂关系"
    ],
    "do_not_copy": ["标题样式", "具体节点位置", "原图文字与页面构图"]
  }
}
```

`style_slots` 与 `tones` 用于确定性路由。没有路由字段时视为所有席位可用。不得把仅供 C/D 的参考图同时传给 A/B 再靠文字要求图片模型忽略。

新 Fast8 对 `reference_images` 执行显式角色校验：只接受 `primary_style_reference`、`supporting_style_reference`、`style_reference` 或已选风格锚点 `style_anchor`。项目源页面、案例证据图、现场照片、产品和 Logo 都属于 `required_assets` 或内容合同的 `required_page_assets`；即使它们具有视觉信息，也不得为了“让模型看见”而伪装成风格参考。整张旧 PPT 页面通常在事实提取后就不再传给图片模型；确实需要其视觉证据时标为 `project_visual_evidence|source_slide|source_page|case_evidence|evidence_reference`，提示只允许模型理解事实或视觉对象，不得复制旧页构图、容器和原文。优先传干净的照片、地图或局部裁切，不传带完整旧版式的截图。Logo、产品图等必须上屏的资产才保留原样使用义务。这样可以避免旧页面把新候选拉回其框架、卡片和信息结构。

### 3. `soft_visual_goals`

描述希望成图达到的感受与质量，不规定实现组件。优先使用正向语言，例如：

- 精致、成熟、有视觉签名、可直接汇报。
- 信息密度适中，复杂关系被少量视觉元素讲清。
- Low 具有开放节奏，同时保留表现力与工艺深度。

不得把软目标改写成卡片数量、分栏方式、节点形状、固定图表、阴影或线型清单。

### 4. `open_decisions`

默认由图片模型决定：

- 内容区构图、视觉媒介、图像工艺和视觉隐喻。
- 具体视觉形式如何组合并服务内容关系。
- 尺度层级、阅读入口、边缘处理和 Takeaway 形式。

只有用户明确要求某种形式，或该形式是事实准确与品牌合规所必需时，才能把它升级为硬约束。

### 5. `qa_only`

详细检查项只供页面控制逻辑和隔离 Judge 审核，不逐条进入图片模型提示词或父级主对话：

- CRAP、空间压力九原则和模糊缩略检查。
- 边缘压力、视觉重量、卡片墙和 Takeaway 角色。
- 内容过载风险、注意力风险和重复负载。
- 工艺完成度、模板感、参考意图命中和跨风格差异。

## 生成提示词边界

Fast8 使用布局合同 v7 和图片提示合同 v6；Fast 4×3 使用布局合同 v6 和图片提示合同 v4。最小提示只保留：

1. 成品级 16:9 商务页面，以及内容合同指定的语言；未指定时保持必显文案的原始语言。
2. `display_required` 的逐字文案，以及 `display_flexible` 中必须传达但允许适度压缩措辞的说明性含义；不翻译、不自行混入另一种语言。新 Fast8 页面合同把前者投影为 `literal_anchors`，并另写一段显式 `flexible_story` 覆盖全部必达含义，不把 JSON 条目边界机械映射为组件边界。
3. 最多三条用户硬要求。新 Fast8 有显式 `flexible_story` 与 `relationship_thesis` 后，提示级语义护栏留在内容合同与 QA，不再重复进入 ImageGen。
4. 若存在已授权的 `global_chrome_contract`，按当前页与 tone 编译一次短标题/页眉模块，并只路由对应的官方 Logo 资产；同一要求不得再出现在 `prompt_user_constraints`。完整授权、适用范围、字体/基线/安全边距和 QA 清单留在全稿合同与独立审查。
5. tone 与 `spatial_standard_version=1` 的统一空间 brief；它用可执行语言表达隐形网格、对齐、聚拢、有限重复、明确对比、有效负空间和密度无关的呼吸感，同时明确不画出网格、不机械铺成等重卡片墙。不得再选择 `low|default`，信息密度继续留在内容合同与 QA。
6. 全部实际风格参考聚合后的 2–3 个核心感觉，并统一说明不继承具体构图、版式、信息结构或原文内容。参考图仍可使四席或八席在核心气质上收敛，但排版和其他视觉决策保持开放。
7. 新 Fast8 与新 4×3 写入页面级 `visual_quality_intent` 和 `relationship_thesis`，并为每席加入互异的 `visual_thesis` 与 `craft_axis`；新 Fast8 另要求 `visual_activity_mode` 与 `attention_strategy`，至少三席为克制的低视觉并发方向，任何席位的次级证据与装饰都不得形成第二套等权叙事。它们不属于事实硬约束，也不是固定版式配方。所有模式的 `direction_id` 都不进入提示。
8. 新 Fast8 在没有风格参考图时仍增加一句成熟度底线：由模型自主建立有鲜明视觉签名的成品设计语言，不能退化为默认企业信息图组件的简单拼装。不展开固定版式或组件清单。艺术导演中若使用具象产品、项目场景或交付结果，必须由来源或附件支持，不能让视觉隐喻冒充事实。
9. 除上述要求外保持视觉决策开放。控制标签随页面语言使用中文或英文；`source|mixed` 以及无专用模板的其他语言使用英文控制文本。

新 4×3 v5 跟随页使用预编译的 v4 图片提示，并默认把本风格锚点成图作为风格附件；本页关系、标题、事实、对象与构图仍只由本页合同决定。当前页事实/品牌资产已占满 5 个附件时，确定性编译器才省略锚点图并使用已锁定的文字化视觉家族，不增加导演判断、Reviewer 或重试。

新 `selected_style_expansion` 也使用 prompt v4，默认 `anchor_input_mode=raster`，传一张 primary、可选一张 supporting 风格锚点。只有锚点媒介与当前页表达存在明确硬冲突，或事实/品牌必要资产占满附件额度时，视觉导演才改用 `text_family`；锚点含旧标题或正文并不单独构成降级理由，因为 prompt v4 已把当前页标题、事实、对象和关系绑定到当前页合同。脚本只验证该决定，不读取锚点文字或增加审查。无论哪种模式，当前页事实、关系、语言、品牌和必要资产都优先，全部真实附件仍不得超过 5 个。

选定风格扩页的非锚点素材还必须显式区分 `render_asset` 与 `planning_evidence`。只有真正要出现在成图中的 Logo、产品图、授权照片等前者可进入 `imagegen_referenced_paths`；旧片截图、架构图、组织图等后者只供导演提取事实并冻结为 supporting source，不能作为 raster 附件。采用写实情境重建且没有授权现场照片时，由视觉导演显式给出源语言 `representation_disclosure`；脚本不按关键词自动增加。

以下内容不得整段复制进生图提示词：

- `source_facts` 全库。
- `overall_requirements` 原文；其中只有不可由其他字段推出的用户硬要求才压缩进入提示。
- 完整 `semantic_invariants`、`forbidden_interpretations` 与母结构解释。
- `content_load_review`、注意力风险和边缘风险。
- 统一空间 brief 之外的长空间说明、详细空间 QA 合同和完整 CRAP 清单。
- `visual_support_goal`、`craft_ambition` 与重复的“精致/成熟/成品级”形容。
- 风格合同中的历史解释、运行状态和重试规则。
- 以形式为对象的长篇禁止清单。

绝对路径不写进提示；图片工具已经按 `imagegen_referenced_paths` 接收附件，提示只用“附件1、附件2”对应其顺序。没有参考图或必要资产时，不得出现泛化的“请使用随附资产”要求。

负面限制优先改写为后果限制。不要针对未被用户指定的媒介或形式建立禁止清单；改为要求任何视觉选择都必须服务核心事实，不得削弱证据关系。

## 风格合同边界

风格合同只锁定：

- 参考图与锚点的角色。
- 色彩、字体气质、图像工艺和整体空间性格。
- 用户明确指定的页面外壳。
- 信息密度、短版空间 brief 和工艺野心。
- 必须稳定的视觉家族特征。

风格合同不得锁定：

- 卡片、圆形节点、虚线、漏斗、分栏等视觉组件。
- 锚点的具体物体、内容结构和页面构图。
- 每页必须出现的 Takeaway 或固定底栏。

使用 `open_dimensions` 明确内容区仍然开放。参考图或锚点本身始终是风格证据，文字合同是辅助说明。

## 工艺门 `craft_gate`

`craft_gate` 检查可观察的质量，不把纯个人喜好机械化：

- 是否明显退化为默认企业模板或通用卡片拼装。
- 是否具有与参考意图一致的视觉签名和工艺完成度。
- 图标、线条、材质、字体和间距是否精细且统一。
- 视觉语言是否真正帮助解释本页关系，而不是装饰或占位。
- 锚点之间是否像不同创意团队，而非同一模板换色。

Fast 4×3 默认不启用阻塞式视觉门。若明确启用可选锚点检查点，只能在该席位创建候选合同和跟随任务之前，对可观察的内容硬伤、结构崩坏或跨锚点实质同构调用一次 `prepare-fast-anchor-repairs`；统一空间标准已经进入生图提示，但选择前的非硬伤空间问题、方向未精确命中和主观偏好都不能触发修复。跟随页选择前不做视觉修复。

新 Fast8 v2 的同一个隔离 Judge 在组合差异之外增加“最低工艺与构图健康过滤”，但不升级为完整 `craft_gate` 或空间 QA：只有单席同时出现至少两类严重、可观察的退化，才可与实质同构共用原有一轮、至多两席的替代预算。允许的客观组合包括默认组件拼装加粗糙容器主导，也包括多个第一层区域竞争加解释模块过载、装饰节点过载加边缘持续受压。轻度卡片感、单个普通框、与参考图不够像或主观“不够漂亮”都不能单独触发。既有 Fast8 v1 Judge 继续只检查差异。

## 规则治理

- 单一项目的一次失败不升级为全局禁令。
- 新问题优先增加 QA 检查或局部修复提示，不追加到通用生图提示词。
- 只有跨多个不同项目反复出现，或涉及事实、品牌、法律与安全的风险，才升级为通用生成约束。
- 新增规则前先合并或删除重复规则，避免只增不减。
- 定期审计生成提示词：正向视觉目标不应被大量负面限制淹没。
