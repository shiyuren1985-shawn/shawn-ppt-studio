# 视觉资产解析与冻结

当用户、大纲或页级资产索引明确要求使用 PDF/PPT/PPTX/DOC/DOCX 某页、网页视口、SVG 或其他非 ImageGen 光栅来源时读取。普通事实来源只参与内容提取，不因“可能有用”而转换成图片附件。

## 统一入口

所有模式共用 `scripts/materialize_visual_asset.py`。它在正式 generation job 冻结前把一个明确定位的视觉来源转换为 PNG，并生成同名 `.materialization.json` 回执；不得由各模式自行复制一套 PDF、Office 或网页截图逻辑。

输入使用一个 JSON spec：

```json
{"source":"/absolute/source.pdf","role":"source_page","locator":{"page":9}}
{"source":"/absolute/source.pptx","role":"source_slide","locator":{"slide":3}}
{"source":"/absolute/source.docx","role":"document_page","locator":{"page":2}}
{"source":"https://example.com/page","role":"web_reference","locator":{"viewport":{"width":1600,"height":900},"wait_ms":1500}}
```

直接调用示例：

```bash
python3 scripts/materialize_visual_asset.py \
  --spec-json '<上面的单个 JSON 对象>' \
  --output-dir '<project_dir>/references/materialized_assets'
```

Fast8 在正式目录创建前通过 `build_fast8_preflight_manifest.py --source-asset-spec '<JSON>'` 调用同一入口。旧的 `--document-page-asset /absolute/file.pdf::页码::role` 仅作为 PDF 兼容别名保留，不再拥有独立转换实现。

## 支持边界

- PNG/JPG/JPEG/WebP：原路径直通，不复制图片；仍生成来源回执。
- PDF：必须指定 `locator.page`，只渲染该页。
- PPT/PPTX/PPTM/ODP：必须指定 `locator.slide`，先隔离转换，再只渲染该页。
- DOC/DOCX/DOCM/ODT/RTF：必须指定 `locator.page`。
- HTML、本地网页、HTTP/HTTPS：使用隔离 Playwright + Chrome 视口，不复用用户正在运行的浏览器会话；默认 1600×900，可显式指定 viewport 和最多 30 秒的 wait。
- SVG/BMP/GIF/HEIC/HEIF/TIFF：转换为 PNG。GIF 只作为静态视觉来源，不承诺动画语义。
- 未支持格式：在正式 job 或 Fast8 正式目录创建前停止并明确报告类型；不得把原文件伪装成图片，也不得为了通过校验改后缀。

网页需要登录、验证码、用户私有会话或动态交互才能到达指定状态时，确定性脚本不得猜测或借用用户当前浏览器。只有这种真实访问阻断，或来源没有提供页码/幻灯片定位时，才请求用户补充；普通可访问来源不增加审批。

## 冻结语义

转换不是新的内容审核层。它只负责“来源定位 → 可用光栅”：

1. 原始本地来源、转换回执和输出光栅分别记录；网页用回执记录 URL、视口和输出身份。
2. 回执与输出按来源内容和 locator 形成稳定身份；相同来源/定位即使角色不同也复用同一个物理 PNG，避免重复占用空间。
3. 输出光栅作为真正 ImageGen 附件；原始文档和回执只用于追溯，不占五个图片附件预算。
4. 先完成全部明确必用来源的转换，再冻结附件清单；冻结后不补丁式添加资产。

Fast8 将原始来源和回执自动加入 preflight 必需来源。4×3 与选定风格扩页由标题/资产导演先调用同一脚本，再把返回的 `output_path` 写为 render asset；源文件继续作为 supporting source，转换回执保留在规范 references 目录。单图修改若用户额外指定非光栅视觉参考，也先经过同一入口，父候选本身不转换、不复制。
