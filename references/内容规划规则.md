# 内容规划规则

## 目的

内容规划负责决定讲什么、按什么逻辑讲，以及哪些事实必须准确。它不负责提前替图片模型决定具体排版。

## 两种有效模式

### 模式 A：自由内容大纲

适用于页数可以变化、希望 AI 自由拆页的项目。

```markdown
# 项目名称

## 受众与目标
- 受众：
- 希望观众最终相信或决定：

## 叙事主线
1. 章节或论点
   - 核心观点：
   - 必须出现的证据：
   - 不可遗漏的信息：

## 资产与限制
- 必须使用的 Logo、图片、截图或数据：
- 不得虚构或不得出现的内容：
```

模型可以自由决定页数、拆页和合页，但必须覆盖全部必讲内容。

自由叙述在进入图片管线前先一次性规范为页面记录；不要让 ImageGen 自己猜页界。

### 模式 B：页面级内容大纲

适用于页数、顺序或内容覆盖需要控制的项目。

```markdown
## 第 N 页｜工作标题
- 核心命题：观众看完本页后应理解的中心主张或关系；可以包含关系明确、共同支撑同一命题的并列重点。
- 完整事实：用于推理、核对和追溯的全部相关事实。
- 逐字必显：必须原样出现的标题、关键数字、名称、术语或用户明确指定文案。
- 说明性必达：观众必须理解、但允许图片模型适度压缩、概括或改写措辞的解释性内容。
- 辅助内容：可摘要、视觉化、移出或留给后续页面的信息。
- 禁止：不能虚构、不能误用或不能提前透露的内容。
- 来源与资产：真实文件路径、页码、工作表或链接。
```

页面级内容大纲到此为止。不要继续添加容器、卡片、分栏、图标位置、构图比例、详细版式或线稿计划。

页面级 Markdown 可以使用表格，也可以使用 `## P2｜标题`、`## Page 2: Title`、`## Slide 2` 或 `## 第 2 页｜标题` 等稳定页标题。页标题之外的受众、全稿目标、统一措辞边界和资料索引只冻结为一次性的 deck context，不得并入某一页；每页到下一个页面标题或同级/更高级章节标题为止。无法形成稳定页界时先规范为页面 JSON，不按相邻文字猜页码。资产路径必须能从当前运行环境访问；Windows 路径、相对路径或链接只作为线索，解析为真实文件后才能成为正式附件。

## 页面内容契约 v2

所有新建图片任务必须把事实完整性与画面展示义务分开：

- `language`：记录当前页最终获授权上屏文案的实际语言，例如 `zh-CN`、`en-US`；用户未指定时写 `source`，表示保持 `display_required` 与 `display_flexible` 的原始语言。中英混合或多语言页面可写 `mixed`，逐项保留原文。`mixed` 只描述当前页实际文案，不表示用户已经请求双语；不得默认 `zh-CN`，也不得让图片模型承担未确认的翻译。
- `language_presentation`：可选的物理页语言合同。`mode` 只用 `zh_only|en_only|bilingual|source`；`delivery` 只用 `single|same_page|split_peer`。`same_page` 必须使用 `mode=bilingual`、`pairing=paired|summary` 和逐项 `pairs=[{"primary":"中文","secondary":"English"}]`；`split_peer` 必须是一中一英两个兄弟物理页，并写相同 `logical_page_id` 与互指的 `peer_page_id`。兄弟页各自只包含一种语言的显示义务，不能互相借文案。`pairs` 只列实际上屏的翻译范围，不要求把本页全部中文翻成英文。`paired` 表示英文紧邻对应中文、共享同一信息单元和关系位置；`summary` 表示英文只作为对应中文主结论的短摘要，仍不得另建底栏、侧栏或第二套信息结构。正式品牌名、产品名和标准名除外。
- `source_facts`：完整事实来源，仅供理解、核对和审核，不表示必须逐条上画面。
- `display_required`：必须直接可见且逐字准确的标题、关键数字、名称、术语、来源或用户明确指定文案。不要把所有解释性长句都塞入此字段。
- `display_flexible`：必须让观众理解的说明性内容；可以压缩、概括、改写或视觉化，但不得改变事实、关系、强弱、时态或结论。它不是可选内容，也不同于 `display_supporting`。
- `flexible_story`：新 Fast8、新 Fast/Strict 4×3 与新 `selected_style_expansion` 的内容导演把全部 `display_flexible` 再压缩成一句不超过 320 字的自然创意简报。它必须覆盖原意，但不逐条重复语义护栏、关系命题或名词清单；ImageGen 使用它，完整 `display_flexible` 继续留在内容合同和 QA 逐项验收。
- `visual_quality_intent`：把用户明确的审美与完成度要求压缩为一句不超过 180 字的结果意图，例如专业克制、工业科技、编辑感或真实材质；不得写固定布局、组件数量、方位或 QA 指令。不要直接复制 `overall_requirements` 长文。
- `relationship_thesis`：用不超过 300 字说明观众第一眼应看见的主次、对比、因果、流向、反馈或证据层级。它是宽定义的页级关系判断，不等于每页强行画隐喻，也不预先指定环形、双栏、流程、卡片、具体物体或其他视觉答案。新 Fast8 与新 4×3 必须填写；其他新页也应优先填写。`relationship_synthesis_brief` 仅作为本轮开发期旧别名读取，新任务不得同时填写两者。
- `display_supporting`：可摘要、视觉化、移出或留到后续页面的次要内容。未获用户许可前不得静默删除，但不要求与视觉重复完整呈现。
- `semantic_invariants` 与 `forbidden_interpretations`：推理和防错约束，默认不渲染为正文、标签或图例。

`forbidden_interpretations` 只记录事实、语义、品牌或合规层面的错误结果，不得放入针对未被用户指定的媒介、组件或构图的审美限制。视觉形式默认属于开放决策；用户明确禁用时才单独记录为用户硬要求。

新 Fast 4×3 与新 `selected_style_expansion` 页面合同写入 `prompt_contract_version=4`；Fast8 使用自己的当前提示合同。所有新运行都按 `参考图与约束分层.md` 分离：

- `spatial_standard_version=1`：新任务统一使用，不再选择或询问 `low|default`。
- `spatial_generation_brief`：逐字使用 `空间节奏与视觉呼吸规范.md` 中对应语言的统一短 brief；它明确整齐布局、隐形网格、对齐、聚拢、有限重复、对比、有效负空间与密度无关的呼吸感。
- `spatial_qa_contract`：只供预检与审核的详细统一空间规则。
- `spatial_feasibility=pass|overloaded`：只有 `pass` 可派发；`overloaded` 必须先完成内容决定。
- `prompt_semantic_guardrails`：0–3 条只有图片模型必须知道的事实防错要求。
- `prompt_user_constraints`：0–3 条无法从内容、资产或方向字段推出的用户硬要求。
- `information_density_target`：`low|medium|high`，只记录内容负载和跨页节奏并留在内容合同与 QA；不编译进图片提示，也不代表呼吸感或空间质量档位。
- `creative_freedom` 或 `open_decisions`：明确内容区构图、媒介和隐喻保持开放。

当 `relationship_thesis` 存在时，图片提示把 `display_required` 显式投影为 `literal_anchors`。新 Fast8、新 Fast/Strict 4×3 与新 `selected_style_expansion` 必须另写显式 `flexible_story`，而不是让脚本机械拼接 `display_flexible`；并把 `visual_quality_intent`、`relationship_thesis`、`craft_axis`、`visual_activity_mode` 与 `attention_strategy` 一并保存为可测试的 `creative_brief_projection`；扩页另保存正向空间拓扑和 `page_adaptation_brief`。它不降低任何内容义务，只避免把合同数组和语义护栏的条目边界误当成等权卡片、行列或组件边界。不同页面可以自然需要顺序、表格或并列；不得把某一页的“不要一行一行”升级成全局形式禁令。

不得把同一要求同时写进 `overall_requirements`、`flexible_story`、语义护栏、用户约束、空间短句和导演方向。新 Fast8 与新 4×3 有显式 `flexible_story` 与 `relationship_thesis` 后，`prompt_semantic_guardrails` 留在合同和 QA，不再重复编入 ImageGen；用户硬要求仍可进入 `prompt_user_constraints`。`semantic_invariants`、`forbidden_interpretations`、长空间规则、视觉支持目标与工艺目标默认属于规划或 QA。

新 Fast8、Fast 4×3 与选定风格扩页都使用 `display_flexible`。新任务不得用一个 `required_content` 同时承载事实库、画面文字和审核约束；旧运行只作只读归档。

从旧大纲或用户材料首次转换为 v2 时，原文标记为“必须出现”“不可遗漏”“全部可见”或同等强度的项目，先全部视为**拟必显集合**。主 Agent 可以建议其中哪些改列为 `display_supporting`，但若页面达到正常可读、内容完整和统一空间标准仍依赖该重分类、概括、少展示实例或不完整展开，必须标记 `overloaded` 并让用户确认；不得先自行压缩后再把页面判为可派发。Fast 候选模式不增加选择前自动空间返修，但新图仍使用同一统一空间标准。

“事实完整”表示事实库、来源与语义约束足以支持准确生成和审核，不表示全部事实都必须发布在单页画面上。`display_required` 与 `display_flexible` 都构成强制画面义务：前者逐字验收，后者按语义验收；`display_supporting` 的最终处理由生成前负载预检和用户确认决定。

## 生成前内容负载预检

在创建图片任务和图片队列前，对当前批次全部页面做一次定性预检。内部记录 `content_load_review`：

```json
{
  "must_render_groups": ["必须直接展示的信息组"],
  "dense_relationships": ["需要同时解释的复杂关系"],
  "visual_channels": ["文字、数字、图表、场景、架构等注意力通道"],
  "semantic_structure": "单一主张、并列双重点、顺序链条或有序多节点",
  "focus_relationship": "各语义重点之间的并列、主从、顺序或共享入口关系",
  "attention_risks": ["可能同时争抢最高强度的无关联区域"],
  "edge_and_takeaway_risks": ["边缘封闭、底部横条或额外标题风险"],
  "duplication_risks": ["可能在长文字与视觉中重复表达的事实"],
  "visual_activity_risks": ["可能让节点、连线、标签、装饰或解释模块同时活跃的因素"],
  "reason": "本页负载判断依据"
}
```

该记录只用于判断，不打分、不设阈值、不引入空间档位。先判断拟必显信息能否形成清楚的页面命题、对齐系统、被组织的视觉入口和主导阅读结构；单一主张、并列双重点、顺序链条或有序多节点是否有明确关系；具体标签、数字、实例和复杂关系是否会迫使多个无关联区域同时以最高强度争抢，或只能靠缩字、压距、挤边、改写义务、少展示实例或不完整展开才能实现。只要存在一种不改变内容义务、同时满足正常可读与统一空间标准的合理组织路径，就写入 `spatial_feasibility=pass`；只有明确需要改变内容义务时才写入 `overloaded` 与 `content_resolution.status=needs_user_decision`。

`content_load_review`、`attention_risks`、`edge_and_takeaway_risks` 与 `duplication_risks` 属于 `qa_only`。页面 Agent 可以用它们理解和审核风险，但不得把这些字段逐条复制到图片模型提示词，也不得把风险诊断改写成长篇形式禁令。

图文重复不是呼吸感的核心定义，只是冗余负载诊断项。文字与视觉承担互补功能，或视觉需要少量文字作为语义锚定时，不构成失败；同一事实被长文字、标签、图例和图形完整重复，且因此造成层级混乱或空间压力时，才进入空间问题判断。

若多页确实达到 `overloaded` 并需要用户决定，必须合并为一次确认，逐页列出移出建议的 `display_supporting`、拆页或调整本页表达范围的影响。不得通过切换空间档位解决过载；用户确认前不得创建图片任务、风格合同或图片队列。

预检解决后，为当前批次每个已解决页面写入一份独立 `content_contracts/page_<ID>.json`。锚点任务、完整 4×3 后续任务和选定风格逐页任务都从该合同机械派生；不得在阶段转换时重新抄写 `source_facts`、`display_required`、`display_flexible`、`display_supporting` 或 `content_resolution`。快速 8×1 首轮只创建共同锚点的内容合同；两个延后页在补页前完成预检后再创建。

### 单一多语言大纲与运行时投影

多语言项目只维护一份权威大纲。每个逻辑页同时保存：完整中文页面内容、完整且已确认的英文页面内容、`bilingual_strategy=same_page|split_zh_en`，以及 `same_page` 实际使用的选择性中英配对。英文完整层用于英文物理页，不等于同页双语时全部上屏；同页双语范围只由配对字段授权。中文与英文都必须属于同一逻辑页，不能从相邻页、锚点或 deck context 借用。

进入新运行前使用 `scripts/project_multilingual_outline.py` 把权威大纲投影为本轮冻结 JSON：

- `--output-mode zh`：每个逻辑页只产生一个中文物理页；JSON 不含该页英文显示层。
- `--output-mode en`：每个逻辑页只产生一个英文物理页；JSON 不含该页中文显示层。
- `--output-mode bilingual`：`same_page` 产生一个 `mixed` 物理页，只含中文内容与获授权配对；`split_zh_en` 产生 `<页码>-ZH`、`<页码>-EN` 两个兄弟物理页，分别只含中文或英文显示层。双语交付不得用英文兄弟页替换中文兄弟页。

投影 JSON 是本轮 source packet 的确定性派生物，不是第二份需要维护的大纲；它必须记录原始大纲绝对路径与哈希。投影完成后，三位导演和 ImageGen 只读投影后的 target-page-only 记录，不再读取完整多语言大纲。`selected_style_expansion` 可以在一个正式运行中包含兄弟页；Fast8 或 4×3 若命中 `split_zh_en` 逻辑页，一次探索只选择一个语言变体，另一语言需要时建立独立运行，不把两种语言混给一个候选。

用户未指定语言时保持源文；明确要求中文、英文或双语时才启用相应投影。来源缺少请求语言的完整页面层时，只阻断对应物理页并报告缺口，不临场翻译、不跨页借词，也不阻断已有合法内容的其他页面。

## 拆页判断

只有在模式 A 中，才让 AI 自由拆页。判断依据是表达任务，而不是预设模板：

- 一页承担多个相互独立的结论时，可以拆页。
- 一个证据需要独立阅读或解释时，可以拆页。
- 一个复杂关系需要先给结论、再解释机制时，可以拆页。
- 两段内容共同支持同一结论且信息量适中，可以合页。
- 用户给出明确页数时，在不丢内容的前提下调整节奏。

拆页完成后，可以生成模式 B 的页面级内容大纲，但仍不写排版。

## 代表页所需信息

为方便自动选择三个代表页，每页应尽量包含：

- 页码或稳定页面标识。
- 工作标题。
- 核心命题；可以包含关系明确、共同支撑同一命题的并列重点。
- 必须出现的内容和素材。
- 信息密度或复杂关系可从内容中判断的充分信息。

## 证据处理

- 对数据、案例、截图和图表记录来源位置。
- 区分事实、推断和建议。
- 证据不足时标记缺口，不得为了页面完整而编造。
- 大纲或当前用户要求明确规定 Logo、标题层级或标题区大致位置时，记录真实来源与资产路径，并写入独立 `global_chrome_contract`，按页与 tone 短编译一次。它只转录来源要求，不增加像素坐标或 Skill 自己的标题规范；QA 只判断明显偏离。大纲没有标题区要求时，不建立该合同、不附加 Logo 或标题位置规则，页面自由发挥。资产库、其他页面或旧母版的存在本身不构成授权。

## 质量检查

- 每页是否形成可理解的核心命题，且并列或多节点内容之间的关系清楚？
- 核心结论是否得到事实或逻辑支持？
- 是否有内容重复、口号化或只讲大道理？
- 所有事实是否在 `source_facts` 与来源中可追溯？
- `display_required` 是否只包含真正需要逐字准确的内容，而不是全部说明文字？
- `display_flexible` 是否都是必须传达、但允许压缩措辞的说明性含义，并在预检负载中按必达内容计算？
- 新 Fast8 与新 4×3 的 `flexible_story` 是否用一段自然语言覆盖全部必达含义，同时删去与语义护栏、关系命题和候选命题的重复？
- `display_supporting` 是否存在重复表达或可移出的次要内容？
- 语义约束是否被误写成画面必须逐条发布的正文？
- 是否把视觉形式禁令误写进 `forbidden_interpretations`？
- 是否使用统一空间短句，并把详细 `spatial_qa_contract` 留在 QA，而不是交给图片模型？
- 提示级语义护栏和用户约束是否短、少、互不重复且没有与导演方向冲突？
- 八席是否用 `visual_activity_mode` 与 `attention_strategy` 真正覆盖低视觉并发方向，而不是都把名词变成节点、标签和解释模块？
- 页面标题是否表达结论，而不是只写主题名？
- 是否误把排版方案写进了内容大纲？
